# 口播驱动商品剪辑规则

> 来源：充电宝口播驱动 V1 / V2 / V3 / V4 / V5-Pro-R1 人工审片。只记录已经通过实际成片验证的规律。

## 1. 主原则

口播驱动剪辑的核心不是“每句话找一个画面”，而是：

`表达意图 → 视觉对象 → 动作/结果峰值 → 人眼可读时间 → 下一语义段`

画面负责证明口播，不是简单陪跑。

## 2. 先拆表达意图，不按句号机械切

每段口播至少输出：

- `spoken_text`
- `intent`
- `selling_point`
- `required_visual`
- `proof_required`
- `ideal_visual_peak`

切镜依据优先级：

1. 语义变化点
2. 动作变化点
3. 口播重音点
4. 句法停顿

句号不能直接等同于剪切点。

## 3. 口播—画面覆盖矩阵

每个语义段必须标记：

- `exact_match`
- `partial_match`
- `no_match`
- `proxy_visual_allowed`
- `proof_missing`

规则：

- exact_match：可以承担功能证明
- partial_match：只能辅助表达，不能冒充完整 Proof
- no_match：禁止用“差不多”的镜头制造不存在的事实

V2 验证：TSA、墙插、促销无直接素材时，诚实使用中性 B-roll 比伪造证明更自然。

## 4. A-roll 与 B-roll 分工

### A-roll

承担：

- 功能动作
- 功能结果
- 核心卖点
- 关键 Proof

必须语义强对应，并满足动作闭环。

### B-roll

承担：

- 痛点
- 便携
- 旅行便利
- 产品氛围
- 过渡
- 结构补充

B-roll 不要求逐词同步，但必须服务当前表达。

## 5. 重音同步：同步动作峰值，不是只同步镜头开始

真正重要的是让视觉峰值落在口播关键词附近。

例如：

- `charges your phone` → Charging 状态出现
- `watch` → 手表充电绿灯出现
- `magnetic / snap` → 实际接触/吸附瞬间

规则：

- 允许画面相对声音提前或延后约 0.2–0.8 秒
- 目标是“语义峰值对齐”，不是“每个单词换一镜”

V2 验证：磁吸接触落在 `snap` 附近，广告感显著强于 V1。

## 6. Proof 对词准确后，仍必须给足可读时间

对词更准不等于更好。

V2 手表段验证：

- 绿灯落点更准
- 但绿灯完整可读时间只有约 0.30 秒
- 真人观感弱于 V1 约 1 秒的稳定停留

因此：

> `sync_accuracy` 不能覆盖 `human_readability`。

核心 Proof 必须同时满足：

- 峰值靠近关键词
- 结果明确出现
- 结果有足够稳定可读时间

## 7. 禁止“逐词打卡式剪辑”

V2 后半段验证：

- 为不同短语频繁拆分近似产品特写
- 13.20–16.40 秒出现同源素材重叠与接口动作重复
- 造成明显机械感

规则：

- 不要因为口播出现新名词就强制换镜
- 同一连续 B-roll 如果能自然覆盖完整语义段，优先保持连续运动
- 相似角度/相似动作不得为“对词”重复使用

## 8. 后半段缺素材时，连续自然优先于频繁代理

当 TSA、墙插、旅行、促销等缺直接素材时：

- 少量中性 B-roll 可接受
- 频繁切近似产品特写会放大“素材不足感”
- 与其逐词找代理，不如保留一段连续、动作自然的产品展示

V1 在 TSA/酒店前半段的连续性优于 V2。

## 9. 功能序列需要呼吸，不要变成“功能清单”

手机 → 手表 → 耳机如果连续快速出现，虽然语义正确，也可能产生 checklist 感。

建议：

- 核心 Proof 之间保留微小呼吸
- 状态重置要明确
- 功能段不能只追求对词速度

## 10. CTA 前必须制造层次升级

V1 的：

`多设备总结 → 单产品 hero`

比 V2 的：

`手持产品 → 手持产品 hero`

收束更强。

规则：

- hero shot 前一镜应尽量在信息、景别或构图上形成反差
- CTA 前不要连续使用两个近似手持产品镜头
- 结尾需要“升级感”，不是又一段同类展示

## 11. Pain Point 不能只看“痛点对象是否出现”

V3 人工审片验证：

- 开头桌面摆着很多线材，只说明“有很多线”，不等于观众已经理解“带一堆充电器很麻烦”。
- 第二段只是把一团线拿起来，如果没有继续移走、扔掉、清空桌面，商业意图仍然没有完成。

因此必须区分：

- `pain_object_visible`
- `pain_action_visible`
- `commercial_intent_completed`

规则：

1. 静态痛点对象只能做极短建立镜头，不能自动承担强 Hook。
2. 优先选择带明确动作的痛点镜头，例如抓起、整理困难、丢弃、移走旧方案。
3. `action_completed != commercial_intent_completed`。
4. Reject Old 必须让旧方案明确退出/被舍弃，单纯“拿起来”不算完成。

## 12. Setup–Payoff 邻接规则

V4 人工审片验证：开头先出现旧线材，隔多个产品/功能片段后才真正把旧线材移走，会让前面的 setup 显得意义不明。

新增字段：

- `setup_role`
- `payoff_role`
- `setup_payoff_distance`
- `setup_standalone_value`

规则：

1. `setup_standalone_value=false` 时，setup 必须靠近 payoff。
2. 如果某个旧方案/痛点镜头的主要价值只是为“后面淘汰它”做铺垫，应优先剪成连续闭环：
   `旧方案出现 → 抓起/处理 → 移走/扔掉 → 清空 → 主产品出现`。
3. 如果无法短时间闭环，则删除 setup，直接从主产品开始；完整的 Reject Old 动作只放在真正对应的口播位置。
4. 不允许 setup 与 payoff 中间隔多个独立功能段，除非 setup 本身拥有足够独立价值。
5. Pain Point 不是必须放在开头；是否放开头取决于它能否比直接产品揭示更快、更清楚、更有冲击地完成表达。

## 13. 方向性 CTA 要找方向性视觉匹配

若口播包含：

- `link below`
- `tap below`
- `swipe up`
- `click here`

应优先搜索与方向一致的手势、指向动作或 UI 反馈。

例如：

`I'll leave the link below.`

如果素材中存在手指指向下方/左下方，它应优先于普通 hero shot，因为这是更强的 `exact_match`。

新增字段：

- `cta_direction`
- `cta_gesture_match`
- `cta_semantic_peak_alignment`

规则：

- 手势峰值尽量落在 `below / swipe / tap / click` 等关键词附近
- hero shot 可以放在 CTA 前承担产品收束，但不能替代更精准的方向性 CTA 动作

V4 人工确认：左下指向 CTA 是明确的正向提升，应保留。

## 14. 主产品动作语义必须安全

V5-Pro 人工反馈发现：主产品在 Hook 阶段被快速向右甩出画面，即使动作本身与口播节奏同步，真人仍会理解成“把要卖的产品扔掉”。

新增字段：

- `action_sentiment_to_target_product = positive | neutral | negative | ambiguous`

规则：

1. Hook / 产品揭示 / 核心展示阶段，只允许 `positive` 或明确 `neutral` 的主产品动作。
2. `negative / ambiguous` 的甩开、推远、离场、丢弃类动作必须淘汰。
3. 动作峰值与口播对齐不能覆盖商业动作语义。
4. 同一种动作对不同对象语义不同：甩掉旧方案可以是正向；甩掉主产品通常是负向。

V5-Pro-R1 验证：将开头替换为产品始终留在画面的正/背面展示与手指演示后，负面动作语义消失。

## 15. readability tail 与 dead tail 必须分开

稳定尾巴不是越长越好。

新增字段：

- `readability_tail`
- `dead_tail`

规则：

- `readability_tail`：用于让观众看清动作结果，可保留。
- `dead_tail`：动作已经结束、没有新信息、只是等待下一句口播，应压缩。
- Hook 前 3 秒尤其严格，不允许明显 dead visual。

V5-Pro-R1 验证：去掉约 1.75 秒无信息停顿后，开头连续保持持握/手指/产品面的信息变化，观感明显改善。

## 16. visual redundancy：不同素材也可能“看起来重复”

不能只查“是否重复用了同一个源文件”。

新增字段：

- `visual_redundancy`
- `same_action`
- `same_information`
- `same_composition`
- `new_visual_information`

规则：

1. 即使源素材不同，只要动作、信息、构图高度重叠，观众仍会认为重复。
2. 镜头保留的核心判断应是：是否提供了新的视觉信息。
3. 如果前面已经完成某个产品面/结构认知，后续近似高度、近似主体位置、近似手持展示必须有额外结构、动作或结果信息才值得保留。
4. 构图、动作、信息三方面都发生真实变化时，才可视为有效视觉推进。

V5-Pro-R1 验证：接口/厚度/侧面电量灯特写与开头正/背面手持展示形成真实信息差，随后切入俯拍磁吸动作，视觉重复问题解决。

## 17. 结构 B-roll 的保留边界

缺直接 Proof 的口播段落可以使用结构 B-roll，但不能为了“有镜头”而机械展示。

规则：

- 连续自然优先于专门端着接口不动。
- 如果一个连续镜头自然经过产品厚度、接口、正面等不同结构，可保留。
- 结构 B-roll 可以辅助 `travel / hotel / convenience` 等语义，但不能冒充不存在的 wall plug / TSA / sale Proof。
- 当候选镜头都有明显缺陷时，信息密度稍降但连续自然的 B-roll 可以视为素材上限，不必为了继续优化强行换差镜头。

V5-Pro-R1 验证：11.57–17.57 连续结构展示虽后段信息密度略降，但连续性自然、有真实结构增量，且无更优候选，因此不值得单独再出一版。

## 18. 纯剪辑阶段应有停止条件

不是版本越多越好。

当同时满足：

- 无必修语义错误
- 无 Proof 损坏
- 无状态跳变
- 无明显视觉重复
- Hook / CTA 成立
- 剩余问题主要来自缺素材或包装不足

则应停止继续重排素材。

下一阶段优先进入：

- 字幕
- 音效
- BGM
- CTA 包装

跨模型导演对照可作为能力实验，但不应成为已经达到素材剪辑上限的成片继续交付的必要步骤。

## 19. 当前最佳融合规则

经 V1/V2/V3/V4/V5-Pro/V5-Pro-R1 审片，当前最佳方向：

- 前半：采用表达意图与重音同步逻辑
- Hook：主产品动作语义必须正向/中性，并避免 dead tail
- 手表：保留 Proof 可读时间
- 磁吸：保留结构预读 + snap 峰值
- 后半：保持连续运动，避免接口重复
- 多设备段：在 `charging all your devices` 附近匹配多设备画面
- CTA：保留 `多设备总结 → hero → 方向性 CTA` 层次
- 旧线材逻辑必须二选一：要么开头一次性闭环，要么直接舍弃开头旧线材，只在对应 `No more carrying...` 处使用完整淘汰动作
- 不只查同源重复，还要检查 `same_action + same_information + same_composition`

## 20. 人工审片必须同时评估三件事

1. `semantic_match`：画面是否说对了
2. `proof_readability`：结果是否看得清
3. `editorial_flow`：整条是否自然、像广告

任何一项高，不能掩盖另外两项低。

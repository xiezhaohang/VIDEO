# Shot Function Library v1

本库不评价“镜头漂不漂亮”，只判断镜头是否完成用户理解任务。每个候选镜头进入时间线前必须回答：它解决用户哪个问题？新增什么理解？删除后损失什么？若第三问答案是“只少一个角度”，默认删除。

## 通用标注合同

```text
shot_id
primary_function
user_question
new_understanding
deletion_loss
entry_state
exit_state
evidence_owner
claim_supported
hold_until
information_upgrade
confidence
```

`primary_function` 只允许一个；可有 secondary，但不能用多标签掩盖任务不清。`information_upgrade` 只能是新 owner、新能力、新数量、新场景、新结果、新意义或更强汇总。

## 功能分类

### Hook

- 用户问题：为什么现在要继续看？
- 新增理解：最强购买意义——结果、问题、发现、体验、身份或外观——已经出现。
- 删除损失：视频失去即时观看理由。
- 合格条件：静音也能看见至少一个购买理由；开箱/包装只有自身具备异常性时才可承担 Hook。
- 退出条件：观众已形成一个明确期待，下一镜必须推进或回答它。
- 证据等级：`validated`。

### Problem

- 用户问题：这与我的哪种麻烦有关？
- 新增理解：当前方案的成本、阻力、风险或不便可被读懂。
- 删除损失：产品介入缺少需求背景。
- 合格条件：痛点必须由动作、结果或清晰对比成立；“桌上有很多线”不自动等于旅行麻烦。
- 退出条件：麻烦已读懂，或旧方案已完成商业意义上的退出。
- 证据等级：`validated`。

### Discovery

- 用户问题：这是什么异常或新东西？
- 新增理解：从局部、包装或陌生形态推进到可识别产品/用途。
- 删除损失：新奇品失去揭晓张力。
- 合格条件：每一状态都缩小未知；悬念不能晚于拥有理由。
- 退出条件：产品身份与第一价值已经可读。
- 证据等级：`strong hypothesis`。

### Proof

- 用户问题：它真的能做到吗？
- 新增理解：同一 owner 完成 Action→Result→Confirmation。
- 删除损失：Claim 只剩口播或主观形容词。
- 合格条件：不能用 Phone 的结果证明 Watch，不能在反馈出现前切走；partial proof 必须明确降级。
- 退出条件：关键结果出现并留到可确认。
- 证据等级：`validated`。

### Transformation

- 用户问题：使用前后到底变了什么？
- 新增理解：before、变化机制与 after 的差异可比较。
- 删除损失：安装/改造只有过程，没有购买收益。
- 合格条件：after 必须与 before 可比较，且不能弱于开场 preview。
- 退出条件：差异与对应收益均已读懂。
- 证据等级：`strong hypothesis`。

### Emotion

- 用户问题：拥有、体验或送出它会是什么感觉？
- 新增理解：圈层身份、关系、仪式、触感或情绪回报。
- 删除损失：视频技术上正确但缺“为什么会选择它”。
- 合格条件：情绪需有产品、人物、动作、声音或场景证据；素材无人际互动时不能空讲关系改善。
- 退出条件：观众能想象一个具体使用者或体验。
- 证据等级：`strong hypothesis`。

### Variety

- 用户问题：有哪种适合我？它覆盖多大范围？
- 新增理解：颜色、版本、问题类型、容量或场景发生有效扩展。
- 删除损失：选择感、丰富度或规模感下降。
- 合格条件：相近角度不算 Variety；每个变体必须形成可辨选择。
- 退出条件：选择空间已足够，不再新增实质差异。
- 证据等级：`validated`。

### Hero

- 用户问题：我最终得到什么？
- 新增理解：把分散 Proof 汇总成一个可拥有的收益状态。
- 删除损失：视频没有视觉句号，功能像清单而不是完整商品价值。
- 合格条件：必须是装好、亮起、读数完成、导入成功、装满、成套或最强感官状态；包装本身通常不合格。
- Hold 理由：首次整合多个已证明状态时，观众需要识别和欲望形成时间。
- 退出条件：整体结果已读懂；后续只允许 CTA 或真正更强 Hero。
- 证据等级：`validated`。

### CTA

- 用户问题：理解价值后下一步做什么？
- 新增理解：购买位置、选择、评论/分享或拥有动作。
- 删除损失：交易/互动路径不明确；但身份型 soft discovery 可无硬 CTA。
- 合格条件：在购买意义和核心 Proof 后出现；`below/tap/click` 需要手势或 UI 方向证据，scarcity 必须可验证。
- 退出条件：动作明确且不再重复同一口令。
- 证据等级：`validated`。

## 删除测试

逐镜执行以下顺序：

1. 删除后，Purchase Motivation 是否仍然成立？
2. 删除后，是否破坏 Claim→Action→Result→Confirmation？
3. 删除后，是否破坏动作连续性或 setup–payoff 邻接？
4. 删除后，是否失去新的对象、数量、选项、场景、结果或意义？
5. 删除后若只损失角度、运动感或时长，该镜头默认冗余。

## 多功能镜头的边界

一个镜头可以同时带来多个可见事实，但 Director 仍需指定主任务。例如“手机和手表同时充电”主任务是 Proof，组合价值可作为 Information secondary。若一个镜头必须靠三句口播才能解释其任务，说明镜头与策略不匹配，应换画面、拆 Claim 或降低置信度。

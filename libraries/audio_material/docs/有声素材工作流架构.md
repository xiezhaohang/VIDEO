# 有声素材工作流架构

## 目标

在不改变稳定 Visual Workflow 的前提下，为声音承担商业价值的素材提供独立、可回退、可实验的 Audio Branch。

## 最小架构

```text
素材输入
  |
  v
显式 Audio Relevance Classifier
  |-- visual_only -----> Visual Workflow（稳定基线）
  |
  `-- audio_relevant --> Audio Branch
                         |-- Audio Role
                         |-- Audio Proof / VO Gap Plan
                         `-- Director / Cutter（继承 Action Integrity）
                                  |
                                  v
                         Sanity Gate / Handoff

Audio Branch 判定失败、证据不足或声音无价值
  `------------------------------------------> Visual Workflow
```

当前不建立更多入口 workflow。细分类只能作为 `audio_relevant` 内部的后续实验，不能改变显式分流和回退边界。

## 分流语义

### visual_only

包括真正无声的素材，也包括虽有音轨但声音不承担商业信息、证明或体验价值的素材。此类素材不调用 Audio Branch。

### audio_relevant

原素材声音本身对观众理解、验证或体验卖点有必要或明显价值，例如音响播放效果、麦克风录音表现、机械结构声或产品语音播报。

判定问题是“声音是否承担价值”，不是“文件是否有音轨”。

## 证据模型

稳定的 Proof Chain 与 Proof Ownership 保持有效：

```text
Claim -> Action -> Result -> Hold
```

Audio Branch 只把 Proof modality 扩展为：

- `visual`
- `audio`
- `audiovisual`

原素材真实声音可以成为结果或确认信息。涉及同步动作时，动作、画面和产品声音应尽量来自同一 continuous take，Action Integrity 仍高于节奏优化。

## 核心证据与包装层

`product_proof` / `music_demo` 是原素材声音承担的核心证据。BGM 与后加 SFX 是包装层。二者必须在角色、来源和混音计划中分开记录，包装层不得伪装成产品真实表现。

## VO Gap / Audio Proof Window

VO 停止不自动代表 dead air。Director 应先检查：

1. 该区间是否需要让观众听到产品真实声音；
2. 声音是否拥有当前 claim 的 Proof Ownership；
3. 是否能保留当前 continuous take 的 sync sound / product audio；
4. 窗口结束后是否仍能安全回到 VO 或 Visual Workflow。

只有前三项不成立时，才把该 VO gap 按普通空白或节奏空间处理。

## 实验边界

- 本次仅完成架构隔离，不宣告任何 Audio Proof 规则有效。
- 不修改当前 `Blind Auto Edit Test 1 — Speaker` 的输入、执行或状态。
- 后续 `Audio Proof v1` 及有声细分实验默认在 `libraries/audio_material/` 内演进。
- 稳定视觉规则仅通过明确路径、版本或 commit 引用；Audio Branch 的草案不得进入旧视觉库。

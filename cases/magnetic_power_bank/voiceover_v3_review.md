# Voiceover V3 人工审片记录

## 用户指出的关键问题

### 1. 开头线材静置镜头意义不足

画面只是展示桌面上的手机、手表、耳机和多条充电线。

问题：
- 如果口播想表达“旅行时不用带一堆充电器”，仅仅展示线材并没有形成明确的痛点动作。
- 观众看到的是“这里有很多线”，但不知道为什么要看它、接下来要发生什么。
- 这类镜头只能算弱 Pain Point，不能自动承担 Hook。

改进方向：
- 优先选择带明确动作的痛点镜头，例如抓起一大把线、整理困难、准备丢弃/移走旧充电器等。
- 静态线材只能非常短地做建立镜头，不能占据重要开头时长。

### 2. 第二个“拿起一堆充电线”动作没有完成表达

画面中手拿起整团线材，但没有明确扔掉、移走、放弃或完成“淘汰旧方案”的动作。

问题：
- 动作发生了，但商业意图没有闭环。
- “拿起来”本身既不是痛点结果，也不是 Reject Old。
- 如果没有继续到“移走/扔掉/清空桌面”，观众会觉得动作意义不明。

通用结论：

> 商业动作也必须遵守 `action_completed != commercial_intent_completed`。

例如：
- 抓起旧线材 ≠ 已经淘汰旧方案
- 必须继续到旧线材被移走/丢弃/退出主要画面，观众才会形成“不要再带这些”的信息闭环。

### 3. CTA 口播应优先匹配“手指指向下方/左下方”的素材

最后口播为：

`I'll leave the link below.`

用户记得原素材中存在一根手指指向左下角的镜头。

如果该素材存在，它比普通产品 hero shot 更接近 exact_match，因为：
- `link below` 是明确方向性 CTA
- 手指向下/左下是直接的视觉语义
- 视觉动作可以在 `below` / `link below` 附近形成峰值

改进方向：
- 下一版必须重新搜索所有 CTA/指向动作候选。
- 若确认存在手指指向下方/左下方，优先用于最后 `I'll leave the link below.`
- hero shot 可以放在 CTA 前作为产品收束，但不应替代更精准的 CTA 动作。

## 本轮新增通用规则

1. Pain Point 镜头不能只判断“画面里有痛点对象”，还要判断痛点是否被观众读懂。
2. 商业动作必须剪到“商业目的完成”的时刻，而不只是物理动作发生。
3. Reject Old 需要旧方案明确退出/被舍弃，单纯拿起不算完成。
4. 方向性 CTA（below / swipe / tap / click）应优先寻找对应方向性手势或 UI 动作，而不是泛用 hero shot。
5. CTA 也需要 `semantic_peak_alignment`：手势峰值应尽量落在 `link below` 等关键词附近。
